- 离线测试轨迹用于留出集评估，真实抓取成功率需要真机新回合测量。

## 38 维适配

Q5 状态/动作顺序均为左臂 7、右臂 7、左手 12、右手 12。模型配置使用 action_dim=38，暂定 10 帧绝对关节目标，不裁剪关节。

已核对本机模型代码与 pi05_base 检查点元数据：

| 参数 | 原检查点 | Q5 |
|---|---|---|
| action_in_proj/kernel | 32 × 1024 | 38 × 1024 |
| action_in_proj/bias | 1024 | 1024 |
| action_out_proj/kernel | 1024 × 32 | 1024 × 38 |
| action_out_proj/bias | 32 | 38 |

官方加载器不会改变这些形状，trainer 会严格校验，因此仅改 action_dim 不足以完成迁移。

首版建议保留预训练主干，重新初始化两组动作投影层：

1. 视觉编码器、语言/动作专家及其他匹配参数复用预训练权重。
2. 动作投影层使用 38 维模型初始化；自定义加载器仅允许明确列出的投影层及新增 LoRA 参数保留初始化，其余缺失或形状不符均报错。
3. 使用与 LIBERO 相同的 `model.get_freeze_filter()`：LLM 非 LoRA 参数冻结；LoRA、视觉编码器、完整动作投影层及时间 MLP 参与训练。首版额外冻结视觉/时间 MLP 的策略已撤回；真实梯度与参数更新仍需在服务器验收。
4. 保存、恢复和推理始终使用同一 38 维配置。

基础模型的前 32 个动作通道不意味着 Q5 前 32 个关节具有相同语义。若比较“复制前 32 维、额外 6 维初始化”，作为不同初始化实验，只用训练/内部验证数据比较。

- pi05=True 时没有 pi0 的连续 state_proj。保留 discrete_state_input=True 使 38 维反馈参与推理；这是功能选择，不是 38 维形状强制要求。
- max_token_len 与 LIBERO 对齐为 200，并检查所有训练状态的任务提示与 token 长度，避免截断。
- image_head 映射为有效主相机，其余模型图像槽位按 OpenPI 掩码约定处理。
- 左手 12 维全零是确认的采集行为，保留通道和监督。执行端固定左手的约定需另行验证，38 维模型输出不保证固定通道恰好为零。

## 验收顺序

1. 固定50/5/10清单，验证三集合读取隔离，只用50条重算38维统计。
2. 完成 Q5 数据适配、38 维配置和权重加载，通过形状检查、真实状态 token 检查及前向推理。
3. 完整模型加载和所有训练均在服务器执行；从 batch 1 测真实更新及显存，确认实际可训练组件更新，不套用 LIBERO 的 batch 16 容量结论。本机仅做 CPU 数据与小型代码检查。
4. 仅用训练集 2–3 条轨迹进行过拟合试验，验证拟合、保存和恢复。
5. 首段约 1000 步训练，按训练/内部验证情况决定预算，冻结候选配置后评估测试集。
6. 离线回放和接口检查通过后安排真机新回合验证。

默认正式学习率仍与LIBERO对齐：预热1000、衰减参考30000、峰值5e-5、末值5e-6，保存/长期保留为1000/5000。首段默认1000步；若首段全在预热，入口要求 --continue-after-segment 明确续跑，否则报错。也允许显式指定较短 --warmup-steps 和 --schedule-steps 做独立短计划，但不会自行改变默认值。总预算仍待服务器吞吐与验证结果确定。
